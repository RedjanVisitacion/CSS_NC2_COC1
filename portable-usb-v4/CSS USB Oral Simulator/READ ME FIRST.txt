# CSS USB Individual Oral

Extract the whole folder. Run CSS USB Oral Simulator.exe or Start Individual Oral.bat and open http://localhost:8767. No Python installation needed. Keep all files together and close the previous server first. To retain scores, copy the old records folder while both servers are closed. For actual USB ejection, run the app from the computer, not from the practice flash drive.

Students enter a name and choose Bootable USB preparation (10 steps) or Clean & format (8 steps). On the virtual desktop, click the bottom search bar, search cmd, and open Command Prompt. Type commands manually. Correct steps turn green and earn one point. Incorrect steps turn red, earn zero, and can be retried. Each step scores once. At completion, Name and Score append automatically to records/Quiz Scores.xlsx. The command report lists every attempt. Refresh resumes this tab's exercise.

All terminal commands are parsed by JavaScript against fictional state. No command is executed by Windows; no physical disk or file is inspected, erased, formatted, or copied.

Scenario: Disk 0 is a 476 GB internal drive. Disk 1 is the USB. D: is the installation source; E: is the USB destination. This classroom exercise assumes an MBR USB, legacy BIOS boot context, suitable boot code/files, and automatic assignment of E: after formatting. active is an MBR step. Copying files alone does not guarantee bootability. UEFI/FAT32 compatibility, files larger than 4 GB, boot code, actual drive letter assignment, and different partition layouts require additional real-world steps. The requested FAT32 for <=32 GB and NTFS for >=64 GB is the scenario's grading rule, not a universal rule.

Commands for boot mode: diskpart; list disk; select disk 1; clean; create part pri; select part 1; format fs=fat32 quick (16/32 GB) or format fs=ntfs quick (64/128 GB); active; exit; xcopy D:\*.* /s/h/f E:\

Format-only mode omits active and xcopy. Full forms create partition primary and select partition 1 are accepted, as are case/spacing differences and equivalent separate /s /h /f switches. Disk numbers and drive letters must match the task. Text such as '(32GB below)' and placeholder '?' are explanations, not literal command arguments.

PowerISO workflow: after exit in boot mode, virtual PowerISO opens. Select a preset OS ISO or browse for an .iso filename. Click Mount image, then Return to CMD. XCOPY succeeds only while the virtual ISO is mounted. Unmount removes the virtual source until mounted again. Browsing reads the filename only; no ISO contents are read or uploaded and nothing is mounted in the Windows host.

Actual USB option: plug in a flash drive, click Detect plugged-in USB drives, and select it. The server uses fixed read-only Get-Disk/Get-Partition metadata queries to list external USB devices, excluding Windows boot/system disks. The exercise uses that device's reported disk number, size and drive letter. Unlettered devices receive a fictional E: in training only. Source D: is fictional, or F: if the USB already uses D:. This metadata remains a snapshot if you remove the drive. No actual clean, format, partition, ISO-mount or copy operation is performed. The explicit Eject button can request real Windows safe removal. Windows metadata queries may be unavailable under some school account permissions; simulated USB mode remains available.

USB detection is automatic on the welcome screen and checks every five seconds while idle. No drive or capacity dropdown is needed. A newly connected USB is selected automatically; otherwise the current detected USB stays selected, or the lowest disk number is used initially. The chosen device is shown before entry. If no USB is connected, a 32 GB simulated drive is used. The assigned USB identity is kept during an exercise; live disconnect/reconnect updates its presence, disk number and drive letter.

Virtual File Explorer: open This PC or the folder icon on the taskbar. Browse training system folders, USB and mounted ISO contents, and sample OS images in Downloads. Open an ISO in virtual PowerISO from Downloads. The USB view shows example files initially, no usable volume after clean, an empty folder after formatting, and installation folders/files after successful XCOPY. View USB files on the result screen opens the copied training files; the taskbar checkmark returns to results. The explorer never reads or modifies actual disk contents.

Explorer uses a dark This PC layout, seven standard folders, simulated drive-capacity bars, and a maximize button. Eject USB is available on the Explorer toolbar, the USB drive right-click menu, and the taskbar USB icon. A safe-removal notification appears and the virtual USB disappears. Reconnect restores the same training volume/files; commands that need the USB are blocked while it is ejected. Eject/reconnect events are included in the report transcript and session recovery. For a purely simulated USB, these actions affect only the training view. For an actual detected USB, Eject requests Windows safe removal (see below).

Live physical USB tracking now continues during the exercise. Disconnecting the assigned USB hides it and blocks USB commands; reinserting the same device restores it, even if its disk number/letter changes. For a real detected drive, Eject now calls Windows CM_Request_Device_EjectW to request safe removal. Windows vetoes are shown without force. The app refuses to eject its own runtime or score-storage drive; run the simulator from the computer and use a separate practice flash drive. Reconnection requires physical unplug/reinsert. Formatting, partitioning, ISO mounting and file copying remain simulated.
